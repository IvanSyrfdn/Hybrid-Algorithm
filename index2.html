Optimasi Penjadwalan Workflow di Cloud Computing: Memetic Algorithm (MA) vs. Hybrid GA-WDO (HMOOP)

Memilih strategi terbaik untuk menekan Makespan, Biaya Sewa VM, dan Risiko Kegagalan Server.

01

Realita Server Cloud

Performa CPU naik-turun, VM butuh waktu booting, dan data antar-server punya ongkos kirim.

Adu Dua Algoritma Hybrid

MA yang fokus waktu dan biaya, melawan Hybrid GA-WDO yang ikut menghitung keandalan.

Simulasi Interaktif

Ubah parameter, lalu lihat jadwal dihitung ulang secara nyata, bukan gambar statis.

Workflow itu rantai tugas, dan cloud tidak pernah ideal

Sebuah workflow ilmiah dimodelkan sebagai DAG: tugas B baru boleh jalan setelah tugas A selesai dan datanya sampai. Di IaaS seperti Amazon EC2, ada tiga kendala yang bikin urusan ini rumit.

01

Dilema cepat-mahal vs murah-lambat

VM kencang mempercepat selesai, tapi tarifnya berlipat. Menekan biaya berarti menunggu lebih lama.

02

Performa CPU turun hingga 24% + booting

Kecepatan nyata VM bisa melorot dari spesifikasi, dan VM baru butuh waktu booting sebelum bisa dipakai.

03

Ongkos kirim data antar-server

Hasil tugas harus dikirim ke VM lain. Bandwidth terkecil di antara dua VM jadi bottleneck.

DAG tugas & transfer data antar-VM

Garis abu-abu: tugas di VM yang sama (transfer 0). Garis amber putus-putus: data harus menyeberang VM.

Dua kandidat algoritma hybrid

Bi-Objective

Memetic Algorithm (MA)

Fokus pada waktu dan biaya. GA klasik yang diberi "bekal" dan diasah dengan pencarian lokal.

  1. LANGKAH 1 / START CERDASPopulasi awal diisi 4 jadwal heuristik: Topo, HEFT, SJF, dan MCO, jadi tidak mulai dari nol.
  2. LANGKAH 2 / KAWIN SILANGDua jadwal digabung dengan PMX (Partially Mapped Crossover) agar urutan tugas tetap valid.
  3. LANGKAH 3 / PERBAIKAN LOKALSwap Mutation menukar posisi tugas, lalu hasilnya dipertahankan kalau lebih baik.
Tri-Objective

Hybrid GA-WDO (HMOOP)

Fokus pada waktu, biaya, dan keandalan. GA mencari dulu, WDO menyempurnakan.

  1. LANGKAH 1 / GA MENCARIGenetic Algorithm menghasilkan kumpulan solusi awal yang cukup bagus.
  2. LANGKAH 2 / MOLEKUL UDARASolusi terbaik GA disuntikkan sebagai "molekul udara" ke Wind Driven Optimization (WDO), lalu partikel bergerak mengikuti tekanan dan angin.
  3. LANGKAH 3 / PARETO ARCHIVENon-dominated Sorting menyaring semua kandidat menjadi kumpulan opsi terbaik yang saling tak terkalahkan.

Lima alasan Hybrid GA-WDO unggul, dan kapan MA tetap juara

  1. 01Menghitung risiko error server. Failure rate ikut jadi tujuan, bukan sekadar bonus.
  2. 02Tahan penurunan CPU 24%. Jadwalnya tetap waras saat performa server melorot.
  3. 03Opsi lebih merata. Nilai Spacing 13-47% lebih rendah, artinya sebaran solusi lebih seragam.
  4. 04Cakupan lebih luas. Hypervolume 35-59% lebih besar, jadi pilihan trade-off lebih beragam.
  5. 05Catatan jujur: pada kondisi stabil, MA tetap kuat dengan 90-100% deadline met.

Logika & rumus perhitungan

Lama kerja tugas
ET = Task_Length / (Kecepatan_VM * (1 - PV))
TERJEMAHAN SEDERHANALama kerja = panjang tugas dibagi kecepatan VM yang sudah dipotong penurunan performa (PV).
Waktu kirim data
TC = Ukuran_Data / min(BW_asal, BW_tujuan) TC = 0 jika di VM yang sama
TERJEMAHAN SEDERHANAKecepatan kirim ditentukan jalur yang paling sempit. Satu VM berarti tidak ada ongkos kirim.
3 nilai rapor
F1 = Makespan F2 = Total Lease Cost F3 = Failure Rate (FT * lambda)
TERJEMAHAN SEDERHANASeberapa cepat selesai, seberapa mahal sewanya, dan seberapa besar peluang server gagal selama tugas berjalan. Makin kecil makin bagus.
Gerak partikel WDO
v_next = (1 - alpha)*v_prev - g*x_cur + |1 - P_opt/P_cur|*(x_opt - x_cur) + (c*v_other)/P_cur
TERJEMAHAN SEDERHANAPartikel melambat karena gesekan, ditarik gravitasi, lalu didorong menuju posisi terbaik. Partikel bertekanan rendah ditarik lebih kuat, ditambah pengaruh partikel lain.

Kesimpulan & panduan praktis

01

Tidak ada algoritma yang selalu menang. Pilihannya tergantung objektif dan seberapa stabil cloud-nya.

02

Memasukkan risiko kegagalan dan penurunan CPU ke dalam tujuan membuat jadwal lebih tahan banting.

03

Pareto Archive memberi banyak opsi. Keputusan akhir tetap di tangan operator sesuai SLA.

Pakai Memetic Algorithm (MA) bila...

  • Performa server relatif stabil.
  • Hanya waktu dan biaya yang jadi pertimbangan.
  • Butuh jawaban cepat dengan deadline met 90-100%.

Pakai Hybrid GA-WDO (HMOOP) bila...

  • Performa server fluktuatif (PV tinggi).
  • Keandalan dan risiko gagal ikut menentukan.
  • Perlu banyak pilihan trade-off yang merata.
